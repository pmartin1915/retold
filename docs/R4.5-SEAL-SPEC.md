# R4.5 spec — Rule-1 sealing: deck-only questions, CompletedTranscript

_Written 2026-10-03. Step R4.5, inserted before R5 by Perry's decision on the R2 Sol audit
(`docs/reviews/R2-SOL-AUDIT-2026-10-03.md`, "Second opinion and decision", item 2). Governing rule:
`docs/PLAN.md` §5.1 (Rule 1: model output is never stored as fact, title or question text). Same contract
as R1–R4: every type, file, rule and test name is fixed here._

## Why

Today Rule 1 holds **by caller discipline, not by types** (the Sonnet second opinion's strongest case).
Two of Sol's findings name the open doors, and R5 is about to add new call sites next to both:

- **Finding 2.** `QuestionTemplate`, `AssembledQuestion` and `Question` can all be built with any text.
  Any future caller could put a string into a persisted `Question` without it coming from the
  audited deck.
- **Finding 4.** `FilingPipeline.file(captureID:segments:)` takes the capture id separately from the
  segments, and `Episode.setExcerpt(from:)` takes any segments at all.
  - `VerifiedSpan.captureID` is copied from `TranscriptWindow.captureID` (`SpanVerifier.swift:108`).
  - So a window built with the wrong id produces spans that cite the wrong capture.
  - `TranscriptWindow` has the same split: its memberwise init pairs any id with any segments.
  - Sealing the window is therefore part of finding 4, not beyond it.

After R4.5, both doors close **at compile time** in a Release build:

- every `QuestionTemplate` is one of the 25 audited deck entries;
- every `AssembledQuestion` came out of `TemplateAssembler`;
- every production `Question` came from an `AssembledQuestion`;
- every `TranscriptWindow` is a slice of a `CompletedTranscript`;
- every `CompletedTranscript` was read off a `.complete` `Capture`.

## Scope

**In:** one new source file, `Retold/Filing/CompletedTranscript.swift`, and edits to six existing source files:

**Out:**

- **No behaviour change.** Every R1–R4 rule computes exactly what it does today. The one exception is the new `setExcerpt` membership guard (§4.3).
- **No deck copy change.** The six `FilingTemplates` move files byte-identical (§1). That is a file move, not a copy edit, so R3's "same file, no lint change" rule for deck copy is untouched.
- No `project.yml` or `.github/` change. CI already has a **Release compile** step (`build.yml`, "Release compile (unsigned, device SDK)"). Any production call to a `#if DEBUG` fixture below therefore fails CI already, so no extra guard is needed.
- No `.user`-origin question constructor. PLAN names no producer for one. That is logged in `ai/IDEAS.md` (§7), and test fixtures still admit `.user`.

## Rule-1 wall (the sealing technique)

Retold is one module, and tests use `@testable import`, which exposes `internal` but never
`fileprivate`. So "hidden" here means a **`fileprivate` initializer declared inside the type's own
body**, in the file named below.

- **Declare these inits in the type body, never in an extension.** An explicit init in the body suppresses the synthesized memberwise init. An init declared in an extension does not, and would leave an `internal` memberwise door open.
- **None of the sealed value types may conform to `Codable`, `Decodable` or `Encodable`.** A synthesized `init(from:)` is a second constructor. This is the exact hole finding 1 describes for `VerifiedSpan`. The sealed value types are `QuestionTemplate`, `AssembledQuestion`, `CompletedTranscript` and `TranscriptWindow`.
- **Test-only constructors are `static func fixture(...)` inside `#if DEBUG`**, the same precedent as `VerifiedSpan.fixture`. CI's Release compile catches any production caller.

## 1. Templates exist only in the deck — `Retold/Questions/QuestionDeck.swift`

Move **`struct QuestionTemplate`** (with `slotMarker` and `slotCount`) and **`enum FilingTemplates`** (its six
statics and `all`) from `TemplateAssembler.swift` to `QuestionDeck.swift`.

- Do not change any id, cue, pattern or order. Keep the doc comments, and update only the file references in them.
- `QuestionTemplate` gets:

```swift
struct QuestionTemplate: Equatable, Sendable {
    let id: String
    let cue: CueKind
    let pattern: String
    // slotMarker, slotCount unchanged

    /// Only this file builds templates: every template in a Release build is a deck entry
    /// (R4.5, Sol R2 finding 2).
    fileprivate init(id: String, cue: CueKind, pattern: String) { ... }

    #if DEBUG
    /// Tests only (non-deck patterns, e.g. a two-slot template). Release builds have no such path.
    static func fixture(id: String, cue: CueKind, pattern: String) -> QuestionTemplate
    #endif
}
```

`QuestionDeck.all`, `QuestionDeck.template(id:)` and every `FilingTemplates.x` reference elsewhere
(`TemplateAssembler.followUps`, `QuestionEngine.broadOffer`, tests) compile unchanged.

## 2. Assembled questions come only from the assembler — `Retold/Filing/TemplateAssembler.swift`

`AssembledQuestion` keeps its four `let`s and gains, in its body:

```swift
fileprivate init(text: String, templateID: String, slots: [VerifiedSpan], cue: CueKind)
```

- `TemplateAssembler.assemble` (same file) is its only caller.
- `func question(createdAt:)` stays, and its body becomes `Question(assembled: self, createdAt: createdAt)`.
- There is no fixture for `AssembledQuestion`. Tests get one by assembling a deck or fixture template.
- **No runtime check** that `templateID` is in `QuestionDeck.all`, anywhere. The type seal is the mechanism. A trap would fire on fixture templates in tests that cannot be run locally.

## 3. Persisted questions come only from assembled ones — `Retold/Model/Entities.swift`

`Question` gets two designated initializers. **Do not use `convenience`**: designated-only matches `Episode`'s
two-init precedent and avoids any `@Model` macro question.

```swift
/// The production constructor: a deck question assembled by Swift from verified spans.
init(assembled: AssembledQuestion, createdAt: Date = Date())
    // id = UUID(); text/templateID/slots/cue copied from `assembled`; origin = .deck;
    // status = .open; askedCount = 0; createdAt as passed.

/// Raw form; only `fixture` calls it. Keeps precondition(origin != .model).
fileprivate init(text: String, templateID: String, slots: [VerifiedSpan], cue: CueKind,
                 origin: Origin, createdAt: Date = Date())

#if DEBUG
/// Tests only: arbitrary text and either non-model origin, for round-trip and engine fixtures.
static func fixture(text: String, templateID: String, slots: [VerifiedSpan], cue: CueKind,
                    origin: Origin, createdAt: Date = Date()) -> Question
#endif
```

- Update the comment above `@Model final class Question`. It should say that `init(assembled:)` is the only production constructor.
- `fileprivate` is also the fallback if the macro objects to anything. Nothing else in `Entities.swift` constructs a `Question`, so the seal is the same.

## 4. CompletedTranscript — new `Retold/Filing/CompletedTranscript.swift`

### 4.1 Types

Move `struct TranscriptWindow` here from `SpanVerifier.swift`.

```swift
/// The frozen transcript of one completed Capture, bound to that capture's id
/// (R4.5, Sol R2 finding 4). Only `Capture.completedTranscript` builds one.
struct CompletedTranscript: Equatable, Sendable {
    let captureID: UUID
    let segments: [TranscriptSegment]

    fileprivate init(captureID: UUID, segments: [TranscriptSegment])

    /// The window over `segments[range]`, carrying this transcript's captureID.
    /// precondition: range.lowerBound >= 0 && range.upperBound <= segments.count.
    func window(_ range: Range<Int>) -> TranscriptWindow

    #if DEBUG
    static func fixture(captureID: UUID = UUID(), segments: [TranscriptSegment]) -> CompletedTranscript
    #endif
}

/// The transcript segments of one capture that a single model call sees (PLAN section 6.3).
/// Only CompletedTranscript.window builds one, so its captureID is always the true one.
struct TranscriptWindow: Equatable, Sendable {
    let captureID: UUID
    let segments: [TranscriptSegment]
    fileprivate init(captureID: UUID, segments: [TranscriptSegment])
}

extension Capture {
    /// The frozen transcript, or nil unless transcriptionStatus == .complete.
    /// segments == transcript exactly: no isFinal filtering, no corrections applied.
    var completedTranscript: CompletedTranscript? { ... }
}
```

- `CompletedTranscript` carries what the capture froze, unfiltered:
  - `SpanVerifier` already ignores non-final runs.
  - The excerpt rule is unchanged (§4.3).
  - Corrections stay an overlay, as R1 defines them.
- `TranscriptWindow` gets **no** fixture. Tests build one through `CompletedTranscript.fixture(...).window(...)` (§6).

### 4.2 Filing — `WindowChunker.swift`, `FilingPipeline.swift`

- `WindowChunker.windows(captureID:segments:maxTokens:overlapTokens:counter:)` becomes `windows(of transcript: CompletedTranscript, maxTokens:overlapTokens:counter:)`.
  - Same algorithm.
  - Counts come from `transcript.segments`.
  - It appends `transcript.window(start..<end)`.
- `FilingPipeline.file(captureID:segments:periodTitles:)` becomes `file(_ transcript: CompletedTranscript, periodTitles: [String])`.
  - The body is unchanged apart from the chunker call.
  - An empty transcript still yields `.noModel(.other)`.

### 4.3 Excerpt — `Entities.swift`

`Episode.setExcerpt(from segments: [TranscriptSegment])` becomes:

```swift
/// The ONLY writer of excerpt. False (excerpt unchanged) unless `transcript` belongs to one of
/// this episode's captures; otherwise the first 25 whitespace-separated words of its segments'
/// texts, joined with single spaces, in order, unaltered (fewer if shorter). R1's word rule.
@discardableResult func setExcerpt(from transcript: CompletedTranscript) -> Bool
```

- The membership check is `captures.contains { $0.id == transcript.captureID }`.
- This guard is the excerpt half of "binds the capture id". Without it, any completed capture's words could become any episode's excerpt.
- The confirm flow (R7) must attach the capture before setting the excerpt.

### 6.3 Compile-time items

These items have no runtime test, and none is to be invented. They are verified by CI compiling with the seals in place, plus the boss grep (§5):

- no `QuestionTemplate`, `AssembledQuestion`, `TranscriptWindow` or `CompletedTranscript` memberwise init is reachable outside its file;

## 7. `ai/IDEAS.md` additions (append-only)

- **`.user`-origin questions have no production constructor (R4.5).**
  - Add `Question.init(typedByUser:)` when a PLAN feature needs one.
  - Decide its `templateID` then. Do not invent one now.
- **The excerpt has no stored link to its capture.**
  - `setExcerpt` checks membership at write time only.
  - Storing the source capture id is a schema change, so it belongs at the V1 freeze.

## Do not

- No new dependency.
- No `try!`, `Task.detached`, `@unchecked Sendable` or `nonisolated(unsafe)`.
- No `!` outside tests.
- No schema change.
- No `Codable` conformance on any sealed type.
- No `convenience` init on `Question`.
- No runtime deck-membership check.
- No change to deck ids, cues, patterns or order.
- No change to any R1–R4 rule's output beyond §4.3's guard.
- No AI attribution in code, comments or commits.

If a test needs a constructor this spec does not provide, **stop and report it**. Do not widen an
access level to make it compile.
