## Second opinion and decision (2026-10-03)

**Second opinion.** Sonnet 5.5 ran fresh-context and was not shown the boss's adjudication, the STATE file or the IDEAS file. It verified each finding against the code and concluded **"HOLDS on current paths."** On finding 3, the stored text is built from the transcript's words (`SpanVerifier.swift:102`). On finding 6, `canonicalTitle` returns the user's own title (`ExtractMerger.swift:93`). On finding 5, the code R4 merged already drops corrected spans. Nothing persists filing output yet. Sonnet's strongest case for "broken": today the rule holds by caller discipline, not by types.

**Decision.** Perry adopted the boss's recommendation:

1. Rule 1 **holds**.
2. **Seal findings 2 and 4 now, as step R4.5, before R5.** R5 adds new assembly call sites. The fixes are code-only, with no schema change:
   - questions are built only from audited deck template ids, and the raw `Question` construction path is hidden;
   - an opaque `CompletedTranscript` binds the capture id to its final segments, for filing and the excerpt.
3. **Finding 1 waits for R7.** Making `VerifiedSpan` non-decodable changes the stored format of `Question.slots`. That is a schema migration, which needs the V1 freeze first.
4. Findings 3, 6, 7 and 8 stay as they are in `ai/IDEAS.md`.
